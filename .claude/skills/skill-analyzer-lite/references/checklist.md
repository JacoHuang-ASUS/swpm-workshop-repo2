# 技能分析檢查清單（權威定義）

共 8 項檢查，不打分數，以【高】【中】【低】問題清單呈現。腳本（`collect_facts.py`）判定其中 6 項，Agent 只判讀 T-1、T-7。

## 結果值

| 結果 | 意義 |
|---|---|
| `pass` | 通過 |
| `fail` | 不通過，列入問題清單 |
| `na` | 不適用（條件不成立，例如沒有腳本） |
| `needs_judgement` | 腳本無法判定，交給 Agent 判讀；Agent 只能改寫成 `pass` 或 `fail`，並附一句理由 |

## 腳本判定項目（照用，不重新判定）

### T-2　description 有「不適用」情況（低）

description 含下列任一字串即 `pass`（不分大小寫）：`不適用`、`不要用`、`不用於`、`不處理`、`not for`、`do not use`、`don't use`。否則 `fail`。

### T-3　有腳本的技能有錯誤處理說明（中）

技能資料夾內有 `.py` 時適用；任一 Markdown 標題含下列任一字串即 `pass`：`錯誤`、`例外`、`失敗`、`error`、`exception`、`troubleshoot`（不分大小寫）。沒有就 `fail`。技能內沒有 `.py` 則為 `na`。

### T-4　SKILL.md 未超過 500 行（低）

行數 ≥ 500 為 `fail`，否則 `pass`。

### T-5　第三方套件都寫進 requirements.txt（中）

1. 以 AST 取得技能內 `.py` 的 import，取模組名第一段，略過相對 import。
2. 排除 Python 內建模組（`sys.stdlib_module_names`）與技能內的本地模組。
3. 以對照表轉成套件名：`sklearn` → `scikit-learn`、`PIL` → `Pillow`、`yaml` → `PyYAML`、`cv2` → `opencv-python`、`bs4` → `beautifulsoup4`。
4. 與 requirements.txt 比對：不分大小寫、`-` 與 `_` 視為相同、忽略版本。requirements.txt 先找技能資料夾，再找目標 repo 根目錄。
5. 有第三方套件未列入 → `fail`；全部列入 → `pass`；沒有第三方 import 且沒有 requirements.txt → `na`。

### T-6　SKILL.md 要求執行的腳本有對應測試（中）

從 SKILL.md 內文抓出 `*.py` 檔名；對每支在目標 repo 內找 `test_<檔名主幹>*.py`（略過 `.git`、`.venv`、`venv`、`node_modules`、`__pycache__`）。有腳本找不到測試 → `fail`；全部找到 → `pass`；SKILL.md 沒提到任何腳本 → `na`。

### T-8　沒有明文密碼、token（高）

掃描技能資料夾內所有文字檔，逐行比對下列三個正規式，任一命中即 `fail`，否則 `pass`。報告與證據只顯示檔名與行號，不顯示命中的值。

```
(?i)(password|passwd|pwd|secret|token|api[_-]?key)\s*[:=]\s*['"][^'"]{6,}['"]
sk-[A-Za-z0-9]{20,}
ghp_[A-Za-z0-9]{30,}
```

修正方向：改從環境變數或不進版控的設定檔讀取，並輪替已外洩的金鑰。

## Agent 判讀項目

只判成 `pass` 或 `fail`，並附一句理由（寫進報告的表格）。

### T-1　description 有「做什麼＋何時用＋觸發關鍵字」（中）

依據：事實 JSON 的 `skill.description` 原文。三項要素都要有才 `pass`：

1. 做什麼：說明技能產出或完成什麼事。
2. 何時用：說明使用情境或時機（例如「當使用者要求……時使用」）。
3. 觸發關鍵字：列出使用者可能說出的具體詞彙（中英文皆可），讓技能容易被選中。

缺任一項即 `fail`；理由要指出缺哪一項。只是籠統一句話（例如只有「處理資料」）視為缺少。

通過範例（虛構技能）：

> 把會議逐字稿整理成待辦事項清單並標註負責人。當使用者提到會議紀要、待辦整理、meeting notes、action items，或貼上逐字稿要求摘要時使用。

理由範例：三項要素齊全，關鍵字含「會議紀要」「action items」。

不通過範例（虛構技能）：

> 會議小幫手。

理由範例：沒說明產出什麼、何時使用，也沒有觸發關鍵字。

### T-7　SKILL.md 寫了「怎樣才算完成」／驗證方式（低）

依據：事實 JSON 的 `skill.headings`；標題不足以判斷時，可唯讀 SKILL.md 該段內文。`pass` 條件：有標題或段落明確說出「做到什麼就算完成」或「如何驗證結果正確」，例如完成條件、驗收標準、檢查清單、輸出檔案存在、測試通過。標題只是「流程」「注意事項」而內文也沒有完成條件，視為 `fail`。

通過範例（虛構技能的標題清單）：

> 目的／流程／輸入格式／怎樣才算完成／錯誤處理

理由範例：有「怎樣才算完成」章節。

不通過範例（虛構技能的標題清單）：

> 簡介／步驟一／步驟二／注意事項

理由範例：標題與內文都沒有說明完成條件或驗證方式。
