# 一頁報告範本

報告存到健檢資料夾的 `.analysis/<目標代號>/<技能名稱>_<MMDD>.md`。以下為結構，`<...>` 處依事實 JSON 填入。報告不得含本機絕對路徑，一律用目標內相對路徑。

---

````markdown
# 技能分析報告：<技能名稱>

- 分析時間：<YYYY-MM-DD HH:MM>
- 目標代號：<目標代號>
- 目標存檔點：<commit 短碼>（有未存檔修改／無未存檔修改）；非 git 目標寫「非 git」

## 結論

<一句話，例如：無【高】問題；【中】2 項、【低】1 項。>

## 8 項檢查

| 代號 | 項目 | 結果 | 說明 |
|---|---|---|---|
| T-1 | description 有做什麼＋何時用＋觸發關鍵字 | ✅／⚠️／❌／➖ | 判讀項填一句理由 |
| T-2 | description 有寫不適用的情況 | … | |
| T-3 | 有腳本的技能有錯誤處理說明 | … | |
| T-4 | SKILL.md 未超過 500 行 | … | |
| T-5 | 第三方套件都寫進 requirements.txt | … | |
| T-6 | SKILL.md 要求執行的腳本有對應測試 | … | |
| T-7 | 有寫怎樣才算完成／驗證方式 | … | 判讀項填一句理由 |
| T-8 | 沒有明文密碼、token | … | |

圖示：✅ 通過／⚠️ 不通過且嚴重度為低／❌ 不通過且嚴重度為中或高／➖ 不適用。

## 問題清單

只列不通過的項目，依【高】→【中】→【低】排序；全部通過時寫「無」。

1. 【嚴重度】T-x 項目名稱
   - 證據：`檔案:行號`（line 為 null 時只寫檔案）
   - 修正建議：<一到兩句>

（T-8 只寫檔案與行號，不寫值。）

## 建議的下一步

1. <最優先要修的事>
2. <選填>
3. <選填>
````
